## 개요

[힙과 타이밍 휠](/posts/cs/algorithm/heap-timing-wheel) 글에서 우선순위 큐를 봤다. 이번 글은 그 우선순위 큐가 가장 유명하게 쓰이는 곳, 최단 경로를 다룬다. 이어서 위상 정렬을 다룬 [DFS와 위상 정렬](/posts/cs/algorithm/dfs-topological-sort) 글과도 한 군데서 만난다.

이 글이 답하는 질문은 두 가지다.

- Dijkstra는 왜 음수 간선이 하나만 있어도 틀리는가?
- Bellman-Ford는 무엇이 달라서 맞고, 그 대가는 무엇인가?

여기서 다루는 문제는 한 출발점에서 다른 모든 정점까지 가는 최소 비용 경로를 구하는 것이다. 이를 단일 출발점 최단 경로(single-source shortest path)라고 한다.

---

## 1. 왜 "음수 간선"이 문제인가

길찾기에서 거리는 음수일 수 없다. 그런데 비용을 거리가 아니라 "순이익"으로 보면 음수가 흔하다. 할인 쿠폰, 환급, 보상 간선이 섞인 비용 그래프가 그렇다.

그래프 하나를 보자. 출발점은 `S`다.

```
        2
   S ------> A ------> C
   |         ^     1
   | 3       | -2
   v         |
   B --------+
```

간선은 네 개다: `S->A=2`, `S->B=3`, `B->A=-2`, `A->C=1`. 눈으로 보면 `S->B->A`가 `3 + (-2) = 1`로 `S->A` 직행(2)보다 싸다. 정답은 다음과 같다.

| 정점 | 최단 거리 | 경로 |
|------|-----------|------|
| A | 1 | S -> B -> A |
| B | 3 | S -> B |
| C | 2 | S -> B -> A -> C |

이제 두 알고리즘이 이 정답에 도달하는지 하나씩 따라간다.

---

## 2. Dijkstra: 가까운 정점부터 확정한다

핵심 아이디어는 한 문장이다. **아직 확정하지 않은 정점 중 거리가 가장 작은 것을 꺼내 "최종값"으로 확정하고, 그 정점의 이웃만 갱신한다.**

구현에서 확정할 정점을 꺼내는 데 우선순위 큐(priority queue)를 쓴다. 간선을 따라 거리를 줄여 보는 연산을 완화(relaxation)라고 한다. `dist[u] + w < dist[v]`면 `dist[v]`를 `dist[u] + w`로 바꾼다.

```
dijkstra(G, s):
  dist[*] = INF; dist[s] = 0
  pq.push((0, s))
  while pq:
    (d, u) = pq.pop()
    if d > dist[u]: continue        # 낡은 항목은 버린다
    for (v, w) in adj[u]:
      if d + w < dist[v]:
        dist[v] = d + w
        pq.push((dist[v], v))
```

"확정해도 된다"는 믿음의 근거는 이렇다. 지금 큐에서 꺼낸 `u`가 가장 가깝다면, 다른 길로 돌아 `u`에 오더라도 이미 그보다 먼 정점을 거치므로 더 길어질 뿐이다. 모든 간선이 0 이상일 때만 성립하는 논리다.

---

## 3. 손으로 따라가기: Dijkstra가 틀리는 순간

앞의 그래프에서 "확정하면 다시 보지 않는" 고전적인 Dijkstra를 한 단계씩 돌린다.

| 단계 | 꺼낸 정점 | 하는 일 | dist (S, A, B, C) | 확정 |
|------|-----------|---------|-------------------|------|
| 0 | - | 시작 | 0, INF, INF, INF | - |
| 1 | S(0) | A=2, B=3으로 갱신 | 0, 2, 3, INF | S |
| 2 | A(2) | C=2+1=3으로 갱신 | 0, 2, 3, 3 | S, A |
| 3 | B(3) | B->A는 3-2=1로 더 짧지만 A는 이미 확정이라 무시 | 0, 2, 3, 3 | S, A, B |
| 4 | C(3) | 이웃 없음 | 0, 2, 3, 3 | 전부 |

결과는 `A=2`, `C=3`이다. 정답은 `A=1`, `C=2`이므로 두 정점이 틀렸다. 틀린 곳은 3단계다. 거리 2에서 A를 확정한 순간, "나중에 더 싼 길은 없다"고 믿었지만 거리 3의 `B`가 -2 간선으로 되돌아와 그 믿음을 깼다. 그리고 틀린 A 값이 C까지 번졌다.

한 가지 짚어 둘 점이 있다. 위 의사코드는 `visited` 표시 없이 낡은 항목만 건너뛴다. 이 경우 3단계에서 `A`가 1로 갱신되어 큐에 다시 들어가고, 이번 그래프에서는 우연히 정답이 나온다. 하지만 이는 정점을 여러 번 처리하는 것이어서 "가까운 순서로 한 번씩"이라는 보장이 사라지고, 음수 간선이 많으면 처리 횟수가 크게 늘 수 있다. Dijkstra를 믿고 쓰면 안 되는 이유는 그대로다.

## 4. Bellman-Ford: 모든 간선을 반복해서 완화한다

핵심 아이디어는 한 문장이다. **확정하지 않고, 모든 간선을 `V-1`번 훑으면서 줄일 수 있으면 줄인다.**

이유는 단순하다. 음수 사이클이 없다면 최단 경로는 같은 정점을 두 번 지나지 않으므로 간선이 최대 `V-1`개다. `k`번째 라운드가 끝나면 간선 `k`개 이하로 갈 수 있는 최단 거리는 이미 반영되어 있다.

```
bellman_ford(G, s):
  dist[*] = INF; dist[s] = 0
  repeat V-1 times:
    for (u, v, w) in edges:
      if dist[u] + w < dist[v]: dist[v] = dist[u] + w
  for (u, v, w) in edges:             # V번째 검사
    if dist[u] + w < dist[v]: 음수 사이클 존재
```

같은 그래프에서 간선을 일부러 불리한 순서 `(A,C), (B,A), (S,B), (S,A)`로 훑는다. `V=4`이므로 3라운드를 돌린다.

| 라운드 | 처리 순서와 결과 | dist (S, A, B, C) |
|--------|------------------|-------------------|
| 시작 | - | 0, INF, INF, INF |
| 1 | A->C, B->A는 INF라 변화 없음. S->B로 B=3. S->A로 A=2 | 0, 2, 3, INF |
| 2 | A->C로 C=3. B->A로 A=3-2=1. 나머지 변화 없음 | 0, 1, 3, 3 |
| 3 | A->C로 C=1+1=2. 나머지 변화 없음 | 0, 1, 3, 2 |
| 검사 | 어떤 간선도 더 줄지 않음 | 음수 사이클 없음 |

`A=1`, `B=3`, `C=2`로 정답과 일치한다. 라운드 2에서 A가 2에서 1로 내려갔는데, 이것이 Dijkstra에게 없던 "확정 취소" 기회다. 간선 순서가 유리하면 더 일찍 끝나지만, 최악의 순서에서도 `V-1`라운드면 충분하다.

### 음수 사이클 탐지

예를 들어 `A->B=-3` 간선이 더해져 `B->A=-2`와 함께 `A -> B -> A` 순환이 생기면, 한 바퀴마다 비용이 5씩 줄어든다. 이를 음수 사이클(negative cycle)이라 하며 이 경우 최단 경로는 정의되지 않는다.

`V-1`라운드 뒤에도 더 줄어드는 간선이 있다면 이 사이클이 도달 가능하다는 뜻이다. 그래서 위 코드의 마지막 검사가 탐지기 역할을 한다. 환율 그래프에서는 간선 가중치를 환율의 음의 로그(`-log rate`)로 두면, 곱해서 1보다 커지는 환전 고리가 음수 사이클이 된다. 이를 찾으면 차익거래 기회다.

## 5. 상수를 더해 음수를 없애면 안 될까

흔한 아이디어다. 가장 작은 가중치가 -2이므로 모든 간선에 `+2`를 하면 전부 0 이상이 된다. 그러나 틀린다.

```
원래 가중치:     S->A=2   S->B=3   B->A=-2   A->C=1
+2 한 가중치:    S->A=4   S->B=5   B->A=0    A->C=3

S에서 C까지
  S -> A -> C        원래 3   +2 후 7   (간선 2개)
  S -> B -> A -> C   원래 2   +2 후 8   (간선 3개)
```

원래는 간선 3개짜리가 더 싸지만, 상수를 더하면 간선 3개짜리가 `3 x 2 = 6`만큼 늘고 2개짜리는 `2 x 2 = 4`만 늘어서 순위가 뒤집힌다. 경로의 간선 수가 `k`면 `k x c`만큼 늘어나기 때문에 간선이 많은 경로가 불공평하게 불리해진다. 최단 경로 자체가 바뀌므로 이 보정은 쓸 수 없다.

음수 간선이 있고 모든 쌍의 최단 경로가 필요하다면 Johnson 알고리즘이 있다. Bellman-Ford로 각 정점의 포텐셜(potential) `h(v)`를 구하고, 간선 `u -> v`의 가중치를 `w + h(u) - h(v)`로 바꿔 모두 0 이상으로 만든 뒤 Dijkstra를 돌린다. 이렇게 바꾸면 s에서 t로 가는 모든 경로의 길이가 똑같이 `h(s) - h(t)`만큼 바뀐다. 간선 수에 비례해 늘던 상수 더하기와 달리 경로 사이의 순위가 그대로 유지된다.

## 6. 비용과 선택 기준

Dijkstra의 `O((V+E) log V)`는 이진 힙 기준이다. 힙에 정점 대신 `(거리, 정점)` 쌍을 다시 넣고 낡은 항목을 버리는 구현은 힙 크기가 최대 `E`가 되지만, `log E`는 `O(log V)`와 같아서 복잡도는 변하지 않는다. 언어 표준 힙이 키 감소(decrease-key)를 지원하지 않는 경우가 많아 이 방식이 단순하고 빠르다. 피보나치 힙을 쓰면 `O(E + V log V)`가 되지만 상수가 커서 실무에서는 드물다.

| 알고리즘 | 시간 | 음수 간선 | 쓰이는 곳 |
|----------|------|-----------|-----------|
| BFS | `O(V+E)` | 불가(가중치가 같다고 가정) | 무가중치 그래프, 0/1 가중치는 덱(deque, 양쪽 끝에서 넣고 빼는 큐)을 쓰는 0-1 BFS |
| Dijkstra | `O((V+E) log V)` | 불가 | 지도 길찾기, 링크 상태 라우팅, 휴리스틱을 더한 A* |
| Bellman-Ford | `O(V*E)` | 가능, 음수 사이클 탐지 | 거리 벡터 라우팅, 환율 차익거래 탐지 |
| Floyd-Warshall | `O(V^3)` | 가능(음수 사이클 없을 때) | 모든 쌍 최단 경로, 작은 그래프 |

그래프가 방향 비순환 그래프(DAG)라면 더 빠른 길이 있다. [위상 정렬](/posts/cs/algorithm/dfs-topological-sort) 순서대로 정점을 한 번씩 완화하면 음수 간선이 있어도 `O(V+E)`에 끝난다. 의존 관계처럼 사이클이 없다는 사실을 아는 경우 우선 이 방법을 떠올릴 만하다.

## 7. 라우팅으로 본 두 알고리즘: ARPANET 교체

두 알고리즘은 네트워크 라우팅의 두 계열과 대응한다. 거리 벡터(distance vector)는 이웃끼리 "내가 각 목적지까지 얼마인지" 표를 주고받으며 계산을 분산하고, 링크 상태(link state)는 모든 노드가 전체 지도를 공유한 뒤 각자 Dijkstra를 돌린다.

### 거리 벡터가 겪는 문제

A - B - C가 일렬로 이어져 있고 링크 비용은 1이다. 목적지는 A다. 정상일 때 B는 1, C는 2다. A-B 링크가 끊긴 직후를 보자.

| 시점 | B의 "A까지" | C의 "A까지" | 일어난 일 |
|------|-------------|-------------|-----------|
| 끊기기 전 | 1 | 2 | 정상 |
| 끊긴 직후 | 모름 | 2 | C의 낡은 광고만 남음 |
| 1 | 3 | 2 | B가 C의 "2"를 믿고 C 경유로 3 |
| 2 | 3 | 4 | C가 B의 "3"을 믿고 B 경유로 4 |
| 3 | 5 | 4 | B가 C의 "4"를 믿고 5 |

두 노드가 서로의 낡은 정보를 믿고 비용을 1씩 키운다. 이를 무한대로 세기(count to infinity)라 하고, 그 사이 A로 가는 패킷은 B와 C 사이를 오간다. 계산이 분산되어 있어서 각 노드가 서로 다른 시점의 정보로 판단하기 때문에 생기는 현상이다.

### 1979년 ARPANET의 교체

이 문제는 실제 네트워크에서 확인됐다. BBN의 McQuillan, Richer, Rosen이 쓴 1980년 논문에 따르면 원래 ARPANET 알고리즘은 각 노드가 자신의 지연 추정표를 128ms마다 이웃 모두에게 보내는 방식이었다. 링크의 "길이"는 출력 큐에 쌓인 패킷 수에 상수를 더한 값이었다. 논문은 다음 문제를 들었다.

- 표가 길고 우선순위가 높아서 정기적으로 보내고 처리하는 것 자체가 트래픽 흐름을 해칠 수 있고, 노드가 100개 이상으로 늘면 더 나빠진다.
- 계산이 분산되어 있어 노드마다 경로가 일관되는지 보장하기 어렵다.
- 혼잡과 토폴로지 변화에는 너무 느리게, 사소한 변화에는 너무 빠르게 반응한다.
- 큐 길이는 지연을 대표하지 못한다. 회선 속도와 패킷 크기가 다르고, 큐가 짧아도 자원을 기다리느라 지연이 길 수 있으며, 같은 부하에서도 큐 길이가 순간순간 크게 요동친다.
- 루프가 몇 초씩 지속될 수 있었고, 패킷이 그 루프에 빨려 들어가 혼잡이 루프 지점에서 시작해 망 전체로 번질 수 있었다.

새 알고리즘은 구조를 바꿨다. 각 노드는 자기 출력 회선의 지연만 담은 작은 갱신(평균 176비트, 노드 수와 무관)을 만들어 모든 노드에 뿌린다(flooding). 갱신은 전달 전에 처리할 필요가 없어서 빠르게 퍼진다. 이미 처리한 갱신인지 알아보는 데 일련번호를 쓴다. 각 노드는 전체 토폴로지 데이터베이스를 갖고 Dijkstra에서 따온 최단 경로 우선(SPF, shortest-path-first) 알고리즘으로 자기를 뿌리로 하는 트리를 계산한다. 지연은 패킷마다 실제로 측정해 10초마다 평균을 내고, 의미 있게 달라졌을 때만 알린다.

논문은 약 6개월 동안 설계와 구현을 했고, 이어 트래픽이 적은 시간대에 실제 망에서 시험했다고 쓴다. 몇 달 동안 두 알고리즘을 망에 함께 올려 두고 실험했으며, 1979년 5월부터 새 방식으로 운영하고 옛 프로그램을 제거했다. 보고된 결과는 다음과 같다.

| 항목 | 논문의 측정 |
|------|-------------|
| 회선 오버헤드 | 1% 미만 |
| CPU 오버헤드 | 2% 미만 |
| 토폴로지 변화 전파 | 대부분의 노드가 약 100ms 안에 인지 |
| 루프 | 일시적으로만 발생. 패킷이 한 노드를 두 번 넘게 지나지 않음 |

루프가 완전히 사라진 것은 아니라는 점에 주의한다. 논문도 새 알고리즘이 루프가 없다고 할 수는 없고, 라우팅이 바뀌는 동안 일시적으로만 생긴다고 쓴다.

### 링크 상태와 거리 벡터의 트레이드오프

| 구분 | 링크 상태(SPF) | 거리 벡터(Bellman-Ford 계열) |
|------|----------------|------------------------------|
| 교환하는 것 | 자기 링크 상태(작음), 전체에 flooding | 자기 거리표, 이웃에게만 |
| 계산 | 각자 전체 지도로 Dijkstra | 이웃 표를 합쳐 분산 계산 |
| 수렴 | 빠르다 | 느리고 count to infinity에 취약 |
| 비용 | 토폴로지 DB 메모리, CPU, flooding | 단순하고 가볍다 |

정리하면 링크 상태는 메모리와 flooding 비용을 내고 빠른 수렴과 일관된 경로를 얻고, 거리 벡터는 단순함을 얻는 대신 수렴이 느리다.

## 결론

- Dijkstra는 "꺼낸 정점의 거리는 최종값"이라는 확정 규칙으로 빠르게 푼다. 이 규칙은 모든 간선이 0 이상일 때만 성립하므로, 음수 간선 하나가 확정한 값을 뒤집고 그 오류가 뒤 정점까지 번진다.
- Bellman-Ford는 확정하지 않고 모든 간선을 `V-1`번 반복해 완화한다. 느리지만 음수 간선을 다루고, 한 번 더 돌려 음수 사이클도 찾는다.
- 모든 가중치에 같은 상수를 더하는 보정은 간선이 많은 경로를 불리하게 만들어 최단 경로를 바꾼다. 음수가 있으면 Bellman-Ford나 Johnson을 쓰고, DAG라면 위상 정렬 순서로 한 번에 푼다.
- 거리 벡터와 링크 상태 라우팅은 각각 Bellman-Ford와 Dijkstra 계열이다. ARPANET은 1979년 5월 전자에서 후자로 옮겼고, 분산 계산의 불일치와 느린 수렴, 지속되는 루프가 이유 중 하나였다.
